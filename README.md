## Маршруты

- `#business` — кабинет бизнеса.
- `#draft` — создание черновика.
- `#edit/<id>` — редактирование задачи.
- `#responses/<id>` — предложения команд по задаче.
- `#catalog` — пока сообщение о неподключённом каталоге.

В браузере проверены переход с главной, создание и редактирование черновика, демо-статусы, количество и просмотр откликов. Основные файлы: `index.html`, `styles.css`, `app.js`. Backend-файлы не изменялись.

## Экран 3 — ввод и уточнение

`#draft` теперь содержит два состояния:

1. Описание (20–4000 символов), тема/отрасль, кнопка «Проанализировать». POST `/api/questions` отправляет `{ task: "Тема: …\nОписание…" }`. Во время запроса видна загрузка, повторная отправка блокируется. Тайм-аут — 45 секунд; уход с экрана отменяет запрос.
2. Минимум три вопроса с ответами, «Сформировать карточку» и «Вернуться к описанию». При неизменённом описании повторный переход сохраняет ответы. При изменении темы или текста вопросы запрашиваются заново.

Ошибки сети, HTTP, JSON и неверная структура вопросов показывают сообщение, возможность повтора и кнопку «Использовать стандартные вопросы». Ответ backend с mode=demo обозначается как стандартные вопросы; mode=fallback предлагает пользователю выбрать стандартные вопросы явно. Для mode=ai отображается AI.

Карточка собирается локально из исходного описания и точных пар вопрос/ответ, без выдуманных фактов, затем открывается редактор. Тема и ответы редактируются и сохраняются вместе с задачей. Публикация не выполняется автоматически. Промежуточное состояние хранится в `ai-sana-draft-wizard-v1`.

На статическом сервере без `/api/questions` работает предусмотренный сценарий ошибки и стандартных вопросов. Для настоящего AI нужен работающий backend с этим endpoint. Существующие backend-файлы не изменялись.

## Редактор карточки и рейтинг

Редактор `#edit/<id>` содержит десять отдельных полей. Ответы предыдущего шага сохранены в раскрываемой подсказке: произвольные AI-вопросы не преобразуются в поля по догадке.

Рейтинг автоматически пересчитывается при вводе. Веса: контекст и потребность 20 (по 10), материалы 20, результат 15, критерии 15, ограничения 10, пользователи 10, связь 10 (контакт и формат по 5). Незаполненные поля и явные значения «Пока неизвестно» не приносят баллов. Оценка полноты предварительная до ручного подтверждения; семантическая экспертиза содержания не проводится.

«Сохранить черновик» сохраняет поля. «Подтвердить карточку» сохраняет снимок текущей версии. После изменения полей публикация требует нового подтверждения. Проверяются название, формат контакта и обнаруженные ссылки HTTP(S). Остальные поля допускается оставить пустыми: публикация не ограничена минимальным рейтингом.

«Опубликовать» создаёт отдельный опубликованный снимок и открывает страницу `#task/<id>`, откуда есть переход в `#catalog`. Каталог показывает все опубликованные задачи и сортирует их по баллу. При редактировании черновика предыдущий опубликованный снимок остаётся доступен до новой публикации. Все операции локальные, в браузере; серверная публикация не подключена.

Проверены формула рейтинга и техническая валидация, повторное подтверждение после изменения поля и публикация карточки с рейтингом 20/100.

## Общий каталог

Каталог доступен с главной для бизнеса и команд, а также по ссылке из кабинета бизнеса. Показаны все опубликованные снимки карточек. Каждая карточка содержит тему, краткое описание, рейтинг, уровень готовности и переход «Подробнее» на страницу задачи.

По умолчанию рейтинг убывает; доступна обратная сортировка. Фильтры темы и уровня работают совместно, кнопка «Сбросить» возвращает все задачи и сортировку по убыванию. Выбор сохраняется при переходе к задаче и обратно в рамках страницы. Для пустого каталога и отсутствия совпадений есть отдельные сообщения. Задачи с рейтингом ниже 40 видны и помечены «Требует уточнения». Отсутствующая тема отображается как «Без темы». При новой публикации тема фиксируется вместе с опубликованной версией.

Проверены границы всех уровней готовности, оба направления сортировки, совместная фильтрация, сброс и открытие задачи с рейтингом 20/100. Данные по-прежнему локальные: для общего каталога между устройствами требуется серверное хранение.

## Страница задачи и предложения

Страница опубликованной задачи показывает полный опубликованный снимок, контакт, формат взаимодействия, рейтинг и семь разделов его расшифровки. Для старых демо-задач, где сохранённый балл не соответствует доступным полям, это явно указано; баллы не подгоняются под демонстрационное значение.

Форма предложения: название команды, идея, краткий план, предполагаемый срок, ссылка HTTP(S) на прототип. Все поля обязательны. Некорректные ссылки и пустые значения показывают ошибку без потери введённого текста. При успешном локальном сохранении выводится подтверждение и статус «На рассмотрении»; форма снова доступна для новых предложений. Нет лимита числа откликов и ограничения по рейтингу, задача остаётся опубликованной. При отказе localStorage предложение откатывается в памяти, форма не очищается и успех не показывается.

Предложения хранят taskId, id, команду, идею, план, срок, ссылку, status=pending и createdAt. Кабинет бизнеса показывает все эти содержательные поля и статус. Это frontend-демо в одном браузере, без серверной отправки и регистрации команд.

В браузере проверены пустая форма, недопустимая ссылка, два предложения разных команд на одну задачу, сохранение после перезагрузки и просмотр обоих откликов бизнесом.

## Главная и выбор роли

- «Я представитель бизнеса» ведёт к маршруту `#business`.
- «Я участник команды» ведёт к маршруту `#catalog`.
- «Открыть общий каталог» также ведёт к `#catalog` без авторизации.

Сейчас эти переходы являются контрактом для следующих экранов. Главная находится в `index.html`, поведение — в `app.js`, оформление — в `styles.css`.

## Модель задачи

Задачи хранятся в `data/tasks.json`; файл создаётся при первой записи.

- `GET /api/tasks` возвращает все задачи.
- `POST /api/tasks` создаёт задачу.
- Для создания обязательны `businessId` и `title`.
- Допустимые статусы: `draft`, `confirmed`, `published`.
- Допустимые уровни готовности: `draft`, `in_progress`, `ready`, `priority`.
- Оценка ограничивается диапазоном 0–100.

## Генератор уточняющих вопросов

Модуль принимает первоначальное описание, отрасль, известные поля карточки и список полей для проверки. В ответ возвращаются:

- отсутствующие поля;
- от 3 до 5 вопросов;
- поле карточки для каждого вопроса;
- факты, подтверждённые входными данными.

### Шаблонные данные

Пока форма и база не подключены к генератору, используйте:

```text
GET http://localhost:3000/api/questions/demo
```

Маршрут возвращает шаблонный вход и результат локального генератора.

### Реальный запрос

```text
POST http://localhost:3000/api/questions
Content-Type: application/json
```

Пример тела:

```json
{
  "description": "Хотим улучшить обслуживание клиентов в розничных магазинах.",
  "industry": "Розничная торговля",
  "knownFields": {
    "context": "Покупатели иногда долго ждут консультанта.",
    "need": "Сократить время ожидания."
  },
  "fieldsToCheck": [
    "context",
    "need",
    "users",
    "data",
    "constraints",
    "expectedResult",
    "successCriteria",
    "contact",
    "interactionFormat"
  ]
}
```

Без `OPENAI_API_KEY` используются локальные шаблонные вопросы. Если ключ задан, сервер вызывает OpenAI Responses API со строгим JSON-форматом. При ошибке или неподтверждённых фактах сервер автоматически возвращается к безопасным шаблонным вопросам.

## Формирование карточки по ответам

AI-операция 2 принимает первоначальное описание, известные поля, вопросы операции 1 и минимум три ответа. Она возвращает одну редактируемую карточку бизнес-задачи, список оставшихся пробелов и источники каждого заполненного поля.
